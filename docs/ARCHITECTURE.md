# Архітектура прототипу Rutzarg

> Стан на: 2026-10-19 · версія 0.1 (vertical slice «Каргат»)

## 1. Загальна схема

```text
 Браузер (гравець 1)        Браузер (гравець 2)
 ┌──────────────────┐       ┌──────────────────┐
 │ Phaser 3 client  │       │ Phaser 3 client  │   рендер, ввід, прогноз руху, UI
 └────────┬─────────┘       └────────┬─────────┘
          │  WebSocket /ws (JSON)    │
          └────────────┬─────────────┘
               ┌───────▼────────┐
               │  server/main   │  HTTP (роздає client/dist) + WS + цикли
               └───────┬────────┘
               ┌───────▼────────────────────────────────────────┐
               │ World (server/sim) — АВТОРИТЕТНИЙ стан світу     │
               │  clock · needs · brain(AI) · social(memory)     │
               │  economy · players · dialogue                   │
               └───────┬────────────────────────────┬───────────┘
                       │                            │ (опційно)
               data/world.json (snapshot)     LLM: Ollama / OpenAI-сумісний
```

Ключові правила з концепту, втілені в коді:

| Правило концепту | Де в коді |
|---|---|
| Сервер — єдине джерело істини (§30.1) | `server/sim/*`; клієнт лише надсилає наміри (`C2S`) |
| Немає паузи / прискорення / перемотування (§13) | `World.tick` викликається таймером сервера; клієнт не керує часом |
| Offline ≠ frozen world (§13.2) | NPC, економіка, в'язниця продовжують жити без гравців |
| Однакові системи для NPC і гравця (§2.4) | `Being` — спільний тип; ринок, потреби, крадіжки, власність справ однакові |
| AI визначає намір, engine — реальність (§2.3) | `brain.ts` обирає активність, виконання в `do*()` перевіряє відстань, гроші, вакансії |
| World Truth ≠ Character Beliefs (§7) | `social.ts`: пам'ять, впевненість, хибна ідентифікація свідком, плітки |
| Phaser не є Game State (§24) | `EntityView` у клієнті — лише відображення снапшоту |
| LLM не симулює світ (§33.11) | `ai/llm.ts` повертає лише намір/репліку; рушій повторно валідує |

TypeScript без етапу компіляції на сервері: Node ≥22.18 виконує `.ts` напряму (type stripping). Тому діє обмеження: **лише стираний синтаксис** (без `enum`, `namespace`, parameter properties), а імпорти пишуться з розширенням `.ts`. Це перевіряє `tsconfig` (`erasableSyntaxOnly`).

## 3. Мережа

- Клієнт надсилає **ввід із фіксованим кроком** `INPUT_DT = 50 мс`: `{t:"input", seq, dx, dy}` (напрям у світових координатах).
- Сервер застосовує кожен ввід тим самим `stepMove()`, але не частіше за реальний час (бюджет `inputBudget`, захист від спідхаку) і підтверджує `ack = lastInputSeq`.
- Клієнт **прогнозує** власний рух. Отримавши снапшот, він бере серверну позицію, відкидає підтверджені входи й переграє непідтверджені (reconciliation).
- Інші сутності клієнт **інтерполює** з відставанням 120 мс між двома снапшотами (10 Гц).
- Клік мишею: клієнт будує шлях (спільний A*) і перетворює його на звичайні входи, тож сервер усе одно валідує кожен крок.
- Події (`say`, `toast`, `dialog`, `chronicle` …) приходять окремими повідомленнями.

Ідентичність: гравець входить в акаунт (email/пароль або Google) і отримує сесійний токен. `join` із сесією відкриває персонажа цього акаунта. Гостьовий режим (якщо дозволено) використовує токен персонажа в `localStorage`.

## 4. Симуляція

### 4.1. Час
`World.time` — ігрові хвилини від створення світу. Прототипний масштаб: `1 с = 1 хв` (`GAME_MINUTES_PER_SECOND`), повний день триває 24 реальні хвилини. За концептом (§13.3) це **не канон**: значення змінюється в одному місці.

Погодинні хуки (`economy.onHour`) обробляють виробництво, о 18:00 продаж і зарплату, о 19:00 прибуток власників. Добові хуки (`onDay`) відповідають за експорт караванами, підвищення платні при дефіциті праці та переманювання працівників.

### 4.2. NPC Brain (concept §33.2)

```text
Level 0 Simulation  → needs.ts, рух по шляху (brain.moveAlongPath)
Level 1 Utility AI  → brain.evaluateOptions(): сон, їжа, робота, пошук роботи,
                       таверна/ринок, цілі (арешт, донос, допомога коханій людині),
                       крадіжка з відчаю, збір боргів, купівля бізнесу, візит до Клумнога
Level 2 Reasoning   → brain.requestJobDecision(): пропозиція роботи → LLM (якщо ввімкнено)
                       або evaluateJobOffer(); результат ПОВТОРНО валідується перед застосуванням
Level 3 Dialogue    → dialogue.ts: шаблони або LLM-репліки (не змінюють світ)
```

Кожні ~10 ігрових хвилин агент переоцінює варіанти. Поточну активність він не змінює без кращої альтернативи (гістерезис). Виконання (`doWork`, `doSteal`, `doArrest`, …) — це «Rules Engine»: перевірка відстані, грошей, видимості, вакансій.

### 4.3. Пам'ять, факти, плітки
- **Fact** описує подію (крадіжка, арешт, найм, борг…), можливо хибну. **Memory** — це факт у голові персонажа з `confidence`, `importance`, `source`.
- **Свідки** (`witness()`): бачать лише ті, хто в радіусі 7 тайлів і в тій самій будівлі (або обидва надворі). Далекий свідок менш упевнений і з імовірністю 25% **помиляється, хто винен** (хибне переконання).
- **Плітки:** агенти поруч діляться найважливішим фактом, якого співрозмовник не знає (впевненість ×0.85). Свої злочини не розповідають.
- **Реакції:** факти змінюють стосунки (довіра, симпатія, страх) і створюють цілі. Вартові отримують ціль «заарештувати», законослухняні свідки — «повідомити варту», закохані — «допомогти з боргом».
- **Тюремний реєстр** (`lastJailedAt`) не дає покарати двічі за ту саму справу.
- **Клумноги** чують новини лише від тих, кому довіряють (жрець Мейлан щоранку переказує Ваелю важливе).

### 4.4. Економіка
- **Ринок** міський: гроші — це міська скарбниця. Ціна залежить від запасу (`marketPrice`), продаж іде зі спредом 20%. Щоденний експорт караванами приносить у місто гроші й не дає цінам обвалитися.
- **Підприємство** (`Business`) має власника (NPC / гравець / `town`), платню, вакансії, дозволені соціальні класи (§21A), касу, склад і вхідну сировину. Виробництво рахується лише тоді, коли робітник **фізично на місці** в робочі години.
- **Зарплата о 18:00.** Якщо в касі не вистачає грошей, у пам'ять робітника записується факт «unpaid», довіра падає, а після 2–4 таких днів (залежно від лояльності) робітник звільняється.
- **Ринок праці:** якщо в підприємстві немає найманих працівників, платня росте. Амбітні власники-NPC переманюють чужих робітників.
- **Книги власника-NPC:** `Business.income` — згладжена денна маржа. Якщо каси бракує, власник доплачує з гаманця. Якщо платня перевищує дохід, він її знижує, а коли резерви вичерпано — звільняє. Не наймає й не переманює людей, яких не потягне (`canAffordHire`).

### 4.4d. Знаряддя, ремонт, позики
- **Добування лише зі знаряддям** (`TOOL_FOR`, shared/gear.ts): деревина — сокира, руда й камінь — кайло, зерно — серп, трави — серп або ніж, саджанець — лопата. Гравцю потрібне знаряддя в руці (з сумки береться саме, `toolFor`). Працівник справи (`JOB_TOOL`: лісопилка — сокира, шахта/кар'єр — кайло, ферма — серп, артіль — лопата) без знаряддя не працює; справа купує його з каси (`supplyTool`, громада доплачує своїм), інакше NPC іде позичати в лихваря (`flags.toolLoan`).
- **Міцність** — `ItemDef.uses` (сокира й кайло 150, серп і лопата 120, ніж 100); стан 0–100 знижується на 100/uses за кожну зібрану одиницю (гравець) або відпрацьовану годину (NPC). На 0 знаряддя ламається.
- **Ремонт** (`repairQuote`/`repairItem`): біля ковадла (залізні речі) чи верстака (дерев'яні, одяг). У чужій майстерні — ціна роботи (≈60% вартості зносу) у касу власника; на своїй/надворі — третина (матеріали) і тренування навички. NPC несуть знаряддя лагодити, коли стан < 35% (план `use: "repair"`). **Викинути** (`discard`) — річ зі слоту або одну копію із сумки.
- **Позики гравцям** (`loans.ts`): у розмові «Попросити в борг» / «Позичити грошей під відсотки». Лихвар дає майже всім (33%, 3 дні; злодіям і боржникам — 50%), знайомі з довірою — менші суми під 0–35% за характером, родина — без відсотків. `Player.loans`; кредитор пам'ятає (`Relation.debt` < 0, факт `loan`). Прострочення: щодня +10% основної суми, недовіра й погрози (`debt_threat`), на 3-й день — скарга варті (ціль арешту `:debt#`); у в'язниці з гаманця стягують на користь кредиторів. Віддати — «Віддати борг» у розмові. Стартові гроші — 45 срібла.

### 4.4c. Житло й оренда, плата за майстерню
- `World.homes[area]` — власник дому: мешканець (на старті — найзаможніший дорослий у домі), громада (храм, резиденція, нові будинки артілі) або справа (`biz: "tavern"` — ціну ліжка встановлює власник таверни, `Business.bedRent`). Запис має `bedRent` (койкомісце за ніч), `houseRent` (увесь будинок; null — не здається цілим), `tenant` (хто винаймає цілий), `rentable`.
- **Хто платить:** о 21:00 (`nightlyRent`) кожен дорослий, хто живе не у своєму домі й не в родині власника чи орендаря, платить за ліжко; орендар цілого будинку — за будинок. Гроші йдуть власнику, у скарбницю громади або в касу справи (журнал: колонка «Оренда / майстерня»). Борг накопичується: NPC після кількох ночей (терпіння господаря + його емпатія) виселяють у таверну, гравця — після 3 ночей.
- **Гравець** (`Player.lodging`): пропозиції (`lodgingOffers`) — вільні ліжка й порожні будинки; винайняти можна лише на місці, перша ніч наперед. Гравці, що винаймають ліжко, займають місце в підрахунку ліжок (`bedsUsed`), а будинок, який винайняв гравець, закритий для заселення NPC. Повноцінний сон (R) — лише вдома чи біля власного ліжка; деінде — дрімота з 0.4 швидкості відновлення.
- **Свій дім:** будинок на вільній ділянці замовляють у резиденції (`commissionPlot` — для гравців і для заможних NPC-орендарів, `npcOwnHouse`). Збудований приватний будинок належить замовнику (`settleOwner`): гравець отримує `lodging.kind = "own"` (без плати), NPC переїжджає з родиною. Власник-гравець вмикає здачу ліжок і ціну (`setLetting`); поки не здає — дім закритий для заселення.
- **Ціни від попиту** (`adjustRents`, щоранку): NPC-господарі, громада й таверна NPC піднімають ціну ліжка на 1, коли місць немає і є ті, кому бракує житла (переповнені доми, лава, бездомні гравці онлайн), і знижують, коли вільна половина ліжок або ціна вища за звичну. Межі — 0.5×..2.5× від початкової (`baseRent`). Ціни гравців не чіпаються.
- **Переповнення:** зайві мешканці (`markNoBed`, останні прибулі) сплять без ліжка — відновлення енергії ×0.55; у таверні платять пів ціни. Гравцю в повній таверні пропонується `bench` (лава, пів ціни, сон 0.6).
- **Табір:** власне ліжко надворі — сон 0.7 (`busy.camp`); у місті (зона `town`) вартовий поруч будить. Без ліжка надворі — 0.4.
- **Майстерні** (`workshopAt`): станція в будівлі належить справі (кузня, вогнище таверни, верстак складу → артіль громади) або власнику дому. Сторонні платять за кожен виріб у `craftOnce` — однаково для гравців і NPC; працівники справи, власник, мешканці — безкоштовно; надворі — безкоштовно. Ціну встановлює власник (`Business.craftFee`, у «Справах»), для справ громади — староста; NPC-власники беруть 1 + жадібність×3. NPC обирають безкоштовну станцію, якщо є.

### 4.4b. Спорядження (одяг, зброя, знаряддя)
- `Being.equip` — шість слотів (`head`, `body`, `legs`, `feet`, `weapon`, `offhand`), у кожному `{ item, dur }` (стан 0–100). Річ — звичайний предмет (`ItemDef.group = "wear"`, `slot`, `stats`): шиється, кується, купується й продається. Знята використана річ потрапляє в `Being.worn` — список станів у сумці, тож вона не «оновлюється» після зняття.
- **Характеристики** (`gearStats`, shared): атака, захист, вигляд, сила = атака + 0.8×захист + бій/5. Знаряддя в руці дає бонус до швидкості збору/роботи (`stats.gather`): сокира — деревина, кайло — руда й камінь, серп — поле.
- **Де це впливає:** швидкість збору гравця й виробітку працівника NPC; спротив арешту (`resistArrest`: якщо підозрюваний помітно сильніший за вартового — шанс відбитися, факт `resisted` зі свідками, вартовий повторить спробу); вигляд кандидата — у голосуванні.
- **Знос:** знаряддя — за кожну одиницю збору / годину роботи, одяг і обладунки — щодня (лише в тих, хто у світі), зброя й обладунки — у бійці. На 0 річ зникає.
- **NPC** (`npcDress`, 7:00 і 17:00): вдягають з сумки, а якщо бракує — ставлять `craftPlan` з `use: "equip"` (купити на ринку або зробити). Бажане залежить від ролі: усім — сорочка, штани, личаки; лісорубу — сокира, шахтарю — кайло, хліборобу — серп, варті — спис/меч і шолом; заможні й амбітні — свита, чоботи, шапка. Старий одяг після заміни викидають.
- **Візуал:** знімок сутності має `g` (голова, тіло, зброя, друга рука) — клієнт малює шапку/шолом, зброю в руці, щит і сірий тон кольчуги поверх спрайта.

### 4.4a. Ремесло (усе у світі можна зробити)
- **Рецепти** — `shared/crafting.ts` (спільні з клієнтом): вхідні предмети, станція (`hand` / верстак / горно / ковадло / вогнище), навичка й час. Ланцюги: деревина → дошки → меблі, стіни; руда + деревина → залізо (горно) → інструменти, ліхтарі (ковадло); камінь → горно, вогнище, кам'яні стіни, колодязь.
- **Предмети, що ставляться** (`ItemDef.obj`), перетворюються на об'єкт мапи. `canPlaceAt` (shared) перевіряє клітинку: вільна, не вода, не ділянка під забудову; блокуючі речі не можна ставити на дорогу, біля дверей, і так, щоб у кімнаті зник прохід. Сервер додатково перевіряє відстань і право: у будівлі можна ставити лише у власному домі чи власній справі. Поставлене записується в `res.placed` (власник) і `res.overrides` (тайл), а світло ліхтарів, горен і вогнищ з'являється й зникає разом з об'єктом (`setTile`).
- **Розбирання** повертає предмет. Забрати чуже (або міське) — це факт крадіжки зі свідками, як кишенькова крадіжка.
- **NPC** мають `craftPlan`: що зробити, скільки й навіщо (`place` / `deliver` / `sell` / `keep`), хто платить (сам або артіль). Виконання — `doCraft`: купити готове чи сировину на ринку → дійти до станції → майструвати (час за навичкою) → використати. Плани виникають із потреб:
  - у домі бракує ліжок → хтось із мешканців робить ліжко й ставить удома (переїзд і нові будинки чекають на нього);
  - на будову потрібні дошки, ліжка, ліхтар, а ринок порожній → будівельник робить сам;
  - громада раз на день ставить ліхтар на найтемнішій вулиці біля дверей (поки є гроші);
  - безробітні майструють на продаж те, чого на ринку бракує і що окупається.

### 4.5. Збереження
Без `DATABASE_URL` знімок пишеться в JSON-файл (атомарно, через tmp-файл). З `DATABASE_URL` — у PostgreSQL (`world_snapshots`) разом із журналом подій і щоденною статистикою. Запис відбувається кожні 60 с і при SIGINT/SIGTERM. Runtime-поля (шляхи, черги LLM) не зберігаються. Версія формату: `SAVE_VERSION`; несумісне збереження ігнорується.

## 5. Клієнт (Phaser 3.90)

- **Проєкція:** ізометрія 2:1, тайл 64×32. `toScreen(x,y) = ((x−y)·32, (x+y)·16)`.
- **Рендер шматками (chunks 16×16 тайлів).** Для мапи 128×128 земля й об'єкти створюються лише для шматків поруч із камерою (кожен шматок має свою RenderTexture для землі й набір Image) і знищуються, коли камера відходить. Зміни окремих тайлів (рубка, посадка, будова) перемальовують лише цей тайл.
- **Об'єкти** — окремі Image з глибиною `depthOf(x,y) = (x+y)·10`. Сутності отримують `+3`, тож у тому самому тайлі вони стоять попереду.
- **Будівлі** складаються з кубів по тайлах (стіни й ступінчастий дах), тому painter's algorithm працює без спеціальних випадків. Коли гравець заходить усередину, дах ховається, а передні стіни опускаються. Мешканців інших будівель не видно.
- **Персонажі** мають 3 шари спрайтшита (одяг, шкіра, волосся) у відтінках сірого, які тонуються кольором персонажа, плюс анімації Phaser `${layer}_${row}_${anim}`. Деталі й контракт для редакторів описано в [ART_PIPELINE.md](ART_PIPELINE.md).
- **Ніч:** окрема сцена-оверлей із RenderTexture темряви, вирізаними джерелами світла (ліхтарі, кузня, вогнище, гай Клумногів) і адитивними ореолами. Підписи та бульбашки малюються над темрявою.
- **UI** — звичайний DOM поверх canvas.

## 6. LLM-інтеграція (опційна)

`server/ai/llm.ts` — одна черга з пріоритетами (0 — розмова з гравцем, 1 — фонове рішення), до 30 задач і одна паралельна, таймаут 15 с. Задачі, що не вмістилися, відкидаються, і спрацьовує fallback.

Контекст будує `agentContext()` (§33.4) лише з того, що персонаж знає: особистість, стан, цілі, стосунки з учасниками й 8 найрелевантніших спогадів. Відповідь LLM для рішень — JSON `{action, counterWage?, reason}` з обмеженого набору дій.

## 7. Як розширювати

- **Нова дія NPC:** додай `ActivityType` у `types.ts`, варіант в `evaluateOptions`, старт у `startActivity`, виконання `doX` в `updateActivity`.
- **Новий тип події, про яку пліткують:** додай `FactType`, важливість у `FACT_IMPORTANCE`, текст у `factText`, реакцію в `reactToFact`.
- **Новий NPC або підприємство:** `seed.ts`.
- **Нова будівля чи зона:** `shared/map.ts` (пізніше дані прийдуть з редактора карт).
- **Нова механіка** має пройти три тести з §32 концепту: чи доступна вона NPC, чи створює причинно-наслідкові зв'язки, і чи не дає абсурдного світу.
